# =====================================================================
# parameter.txt — RK3188 aDesk-STD-200H-s / Linux 6.12（第四版修正）
#
# 相对上一版（路线 A：root=/dev/mmcblk1p1 + mtdparts + 擦 MBR）的修改：
#
#   [1] CMDLINE 增加 blkdevparts=mmcblk1:-@20M(rootfs)
#       —— 这是本次唯一实质修复。
#
#       上一版失败原因（第五轮 TTL 日志 ttl-rz4.txt 第 230-247 行）：
#         /dev/root: Can't open blockdev
#         VFS: Cannot open root device "/dev/mmcblk1p1"
#              or unknown-block(179,1): error -6
#         List of all partitions:
#         b300  3866624 mmcblk1        <- 只有整盘，没有任何 p1
#         b320     2048 mmcblk1boot0
#         b340     2048 mmcblk1boot1
#
#       minor=1 就是 mmcblk1p1，内核在“分区表扫描”阶段没找到它 → 说明 eMMC
#       上根本不存在 MBR/GPT。“擦 MBR 让 loader 重建分区表”这个假设不成立：
#       老 RK3188 SDK（Boot ver 2013-12-27#2.10）是按 parameter 里的绝对扇区
#       偏移裸写镜像，从来不写分区表；而且扇区 0 是 loader 本体，MBR 想写也没
#       地方写。
#
#       既然磁盘上永远不会有分区表，就必须让“内核自己”把分区造出来。
#       主线内核给 eMMC 无分区表场景准备的机制就是 blkdevparts
#       （block/partitions/cmdline.c，源码注释原话：
#        "Typically used for fixed block (eMMC) embedded devices.
#         It has no MBR, so saves storage space."）。
#       语法（6.12 源码 + 官方文档 block/cmdline-partition.rst 双证）：
#         blkdevparts=<磁盘名>:<size>[@<offset>](<名字>),...
#         size 为 "-" 表示“剩余全部”；size/offset 单位是字节，支持 K/M/G 后缀，
#         内核内部 >>9 换成 512B 扇区。
#       所以 blkdevparts=mmcblk1:-@20M(rootfs)
#          = 在 mmcblk1 上建 1 个分区：起点 20MiB，长度到盘尾，名字 rootfs
#          = 内核里就是 /dev/mmcblk1p1（槽位从 1 开始编号）。
#
#   [2] root= 保持 /dev/mmcblk1p1（与 blkdevparts 建出的分区号严格对应）
#       本方案只建 rootfs 一个分区，所以它是 p1。
#       若改成“先 boot 后 rootfs”，则 boot=p1、rootfs=p2，root= 必须写 p2。
#       本方案故意不建 boot 分区：内核不需要它（loader 用绝对偏移读 boot.img），
#       少一个分区就少一次“对号入座”出错的机会。
#
#   [3] 删除“刷机前 dd 擦 eMMC 前 1MiB”的错误指引
#       前 1MiB 里是 loader，擦了只会让盒子进不了 loader（要拆机进 maskrom 救），
#       对“让 mmcblk1p1 出现”没有任何帮助。
#
#   [4] 保留 mtdparts=rk29xxnand:0x00008000@0x00002000(boot),-@0x0000A000(rootfs)
#       它是给 RKDevTool / loader 用的“烧写布局”（boot 写 4MiB 处 16MiB，
#       rootfs 从 20MiB 起写），和内核 blkdevparts 是两个体系，必须都留：
#         mtdparts   ：决定镜像写到 eMMC 的哪个物理位置
#         blkdevparts：决定内核把这些位置识别成哪个 /dev 分区
#       两者偏移必须一致，否则内核分区指到的不是你写进去的数据。
#       扇区换算：0x2000 ×512 = 4MiB，0x8000 ×512 = 16MiB，0xA000 ×512 = 20MiB。
#
#   [5] 删除 initrd=0x62000000,0x00800000（无 initramfs，留着会报
#       "Initramfs unpacking failed: invalid magic"）。
#
#   [6] 保留 dwc_driver=2（老 BSP 的 USB 参数，6.12 忽略；日志里出现
#       "Unknown kernel command line parameters" 属正常现象）。
#
#   前置条件（编译期由 build.yml 强制校验，缺一项 CI 直接失败）：
#     CONFIG_PARTITION_ADVANCED=y
#     CONFIG_CMDLINE_PARTITION=y   <- 少了它 blkdevparts 在内核里不生效
#
#   刷机后 TTL 日志应出现（验证标志）：
#     Kernel command line: ... blkdevparts=mmcblk1:-@20M(rootfs) ...
#     mmcblk1: p1                                  <- 分区表扫描成功
#     EXT4-fs (mmcblk1p1): mounted filesystem with ordered data mode
#     Run /sbin/init as init process
# =====================================================================
CMDLINE:earlyprintk console=ttyS2,115200 root=/dev/mmcblk1p1 rootfstype=ext4 rw rootwait init=/sbin/init maxcpus=1 blkdevparts=mmcblk1:-@20M(rootfs) mtdparts=rk29xxnand:0x00008000@0x00002000(boot),-@0x0000A000(rootfs) dwc_driver=2
